## The automation question

Language models have been superhuman at chat for years, so where's the automation? TypeSafe AI asks that in its Jev launch post. The problem isn't intelligence. Code needs `true` or `false`, one of five categories, a number between 0 and 1. An LLM gives you a paragraph, so you write a fragile parser, a retry loop for the day it wraps the JSON in markdown, and wait ten seconds while it thinks out loud.

TypeSafe's answer is a new class it calls a **System One model**. Jev is the first.

## System 1 vs. System 2

*System 2* is slow, deliberate thinking: chess, writing an essay. *System 1* is instant: "is this email spam?" You don't reason through it, you just know. LLMs are System 2 machines even when the task is System 1. Routing a support ticket with one is like hiring a novelist to stamp envelopes. It works, but it's slow, it's pricey, and now and then you get a short story back.

> Think of Jev as a frontier-intelligence function call: unstructured state in, typed probabilistic decisions out.

## What Jev actually is

Jev is a *decision model*. You give it some **state** (text, a JSON object or an array) and typed **questions**, each with its own instructions. It returns typed answers with probabilities. There are three question types:

<div class="uc">
<div><b>boolean</b>Yes or no, as a probability from 0 to 1. <em>"Is the customer asking for a refund?"</em> gives <code>0.98</code>.</div>
<div><b>choice</b>Pick one from a set you define, with a probability for each option. <em>"Route this ticket"</em> gives <code>billing: 0.97, shipping: 0.02, technical: 0.01</code>.</div>
<div><b>score</b>Rate something on an ordered scale you describe, like poor / fair / good / excellent. You get an interpolated score such as <code>2.97</code> plus the probability of each rung.</div>
</div>

A full call through the Vercel AI SDK:

```ts
import { experimental_decide as decide } from 'ai';

const result = await decide({
  model: 'typesafe-ai/jev',
  state: 'I cannot log in, and I also want a refund for last month.',
  questions: {
    authIssue:   { type: 'boolean', instructions: 'Is there a login problem?' },
    wantsRefund: { type: 'boolean', instructions: 'Is a refund requested?' },
    urgency:     { type: 'score', instructions: 'How urgent is this?',
                   criteria: ['low', 'medium', 'high'] },
  },
});

result.answers.wantsRefund.probability; // 0.97
```

No begging for JSON and no repair step. The model can't produce a malformed answer.

## Why it's fast and cheap

An LLM writes one token at a time, and each depends on all the ones before it. Nothing runs in parallel, so the wait grows with the answer. That's *autoregressive* generation.

Jev is trained with **Reinforcement Learning for Calibrated Decisions (RLCD)** and samples every answer **in parallel** in one pass. The output is a small fixed-shape structure, so there's nothing to stream.

<TokenRace />

TypeSafe reports **70 to 500 ms end to end**, **40× to 200× faster** than frontier LLMs on comparable tasks. In its benchmark a Jev case took about 0.4 s against 10 to 38 s.

On cost, Jev charges **$0.042 per million input tokens** and nothing for output, and a chatty LLM answer is mostly output. Extra questions are nearly free too, since every question runs in parallel against the same state and adds only its own tokens. One cookbook example asked 13 questions in one call and came out 12.2× cheaper and 10× faster than asking them one by one.

TypeSafe puts a typical support ticket at about **$0.0000126** and 1,018 research papers at **$0.08**.

## Is it actually good, though?

TypeSafe's benchmark assumes a correct workflow in code and uses the biggest models' predictions as reference probabilities. The result:

Jev roughly ties one big model and trails the best by about six points, at 75× to 450× less per case going by those ranges. For a decision you make a million times a day, that's often an easy trade. For one high-stakes call, maybe not.

## Calibrated confidence is the killer feature

An LLM will say it's 95% sure about almost anything. Jev is trained so that *higher confidence means higher accuracy*, which changes how you build:

```ts
const { probability } = answers.isSafe;

if (probability > 0.95)      runIt();
else if (probability > 0.60) askHuman();
else                         reject();
```

Jev takes the sure cases and flags the rest. Vercel's AI Gateway can even re-run a request on a bigger model when Jev's confidence lands in an uncertain band: cheap by default, expensive only when it matters.

## Where it shines

<div class="uc">
<div><b>Routing and triage</b>Tickets, forms, emails, leads. Ask ten questions (topic, urgency, sentiment) in one call.</div>
<div><b>Guardrails for other AI</b>Ask "is this shell command destructive?" before an agent's tool calls. It's cheap enough to check <em>every</em> action.</div>
<div><b>Bulk labeling</b>Classify a thousand papers or reviews for pennies.</div>
<div><b>LLM-as-judge, minus the bill</b>Score outputs against a rubric in evals or CI.</div>
<div><b>Semantic search and re-ranking</b>Score candidates against a query with no embeddings or vector database, as in my project below.</div>
<div><b>Real-time agents</b>Early demos steer a Minecraft bot (two minutes reportedly cost about a cent) and driving and drone sims. They're simulators, so treat them as a hint.</div>
<div><b>Feature engineering</b>Turn free text into numeric columns ("how angry, 0 to 3?") for a classical model.</div>

## Case study: a search engine built from a function call

I built **PageLens**, a Chrome extension that highlights the passages on a page that answer your question, by meaning rather than keyword. No embeddings, no vector store. The page is split into chunks, and each chunk becomes *one score question* in a single Jev call.

```ts
questions[chunkId] = {
  type: 'score',
  instructions: `How relevant is passage ${chunkId} to the query?`,
  criteria: ['not relevant', 'somewhat relevant', 'relevant', 'highly relevant'],
};
```

Scoring 80+ passages takes about as long as scoring one.

### Lessons from production

- **Documented limits aren't usable limits.** The docs say tens of thousands of tokens. In my testing 89 questions (~15k tokens) worked repeatedly, while ~118 (~20k tokens) hit persistent 503s. Oversized batches fail outright. PageLens caps batches at 12k tokens / 80 questions and measures with `result.usage.inputTokens`.
- **Each question must know who it is.** All questions share one state, and with identical instructions Jev gave nearly the same answer every time: `2.95, 2.95, 2.96, 2.96` on passages that should have spanned 0 to 3. Putting the chunk id in each question's instructions fixed it: `0, 3, 0, 1.19`.
- **Don't spend Jev where a regex will do.** Checking whether a query is an exact phrase is plain string work. Save the model for meaning.

## What Jev is not

- **It can't write.** No summaries or explanations, only structured answers.
- **No deliberate reasoning.** It's unreliable at counting, arithmetic and date comparisons, and contradictory criteria confuse it.
- **Text only, for now.**
- **Caps:** up to 255 choices per question. Early access rate limits were around 1,200 requests/minute and 250k tokens/second, and are dynamic.
- **Vendor benchmarks.** The numbers are TypeSafe's own and the demos are simulators. Test on your own data.

## A pattern worth stealing

1. **Ask everything at once.** Break the decision into many small questions in one call. It's nearly free.
2. **Combine in code.** Weight the probabilities yourself, so the logic stays testable instead of buried in a prompt.
3. **Threshold on confidence.** Automate the sure cases, escalate the rest to a big model or a human.

## The takeaway

Jev bets that most of what software needs from AI isn't conversation, but a fast, cheap, calibrated judgement inside an `if` statement. If that's right, the next AI features won't look like chat boxes.

Try it on one boring classification job you're paying a big model for, and compare the bill.
